# Contributing

Thanks for contributing to Watermelon Corp projects.

## Before You Start

1. Check the repository README for project-specific setup.
2. Open an issue first for large changes, refactors, or new feature areas.
3. Keep pull requests focused and easy to review.

## Development Expectations

1. Work from a branch instead of pushing directly to `main`.
2. Follow the repository's lint, typecheck, and build steps before opening a pull request.
3. Update docs when behavior, APIs, installation, or contributor workflows change.
4. Add tests when the repository already has a testing pattern for that area.

## Pull Requests

1. Explain the user-facing change and why it is needed.
2. Link the related issue when there is one.
3. Include screenshots or recordings for UI changes.
4. Call out breaking changes clearly.

## Communication

Be respectful, assume good intent, and keep feedback specific to the work.

For repository-specific rules, the local docs in that repository always win over this shared default.
