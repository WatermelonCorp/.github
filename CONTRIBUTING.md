# Contributing

Thanks for contributing to Watermelon projects.

## The Easy Path

1. Find the repo that matches the change.
2. Read that repo's `README.md` for setup and structure.
3. Create a focused branch for one change.
4. Run the repo checks before opening a pull request.
5. Include context, screenshots, and follow-up notes in the PR.

## What To Contribute

Good first contributions include:

- bug fixes
- documentation cleanup
- accessibility improvements
- missing examples
- better component demos
- contributor experience improvements

For bigger changes, open an issue or discussion first so we can align on direction.

## Working Style

- Keep pull requests small enough to review quickly
- Update docs when setup, APIs, or workflows change
- Add tests when the repo already has a clear test pattern for the area
- Be explicit about tradeoffs, edge cases, and breaking changes

## Pull Request Checklist

Before opening a PR, please make sure:

1. The change is scoped and understandable on its own.
2. The relevant build, lint, and typecheck commands pass locally.
3. UI changes include screenshots or a short recording.
4. Related issues are linked when they exist.
5. Docs are updated if contributors or users will notice the change.

## Community Expectations

Please be respectful, assume good intent, and keep feedback specific to the work. By participating, you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

Repo-specific documentation always wins over this shared default when there is a conflict.
